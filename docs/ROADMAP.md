## Phase 2: 공통 모듈 개발 (2-3일)

### 🎯 왜 이 순서인가?
**모든 기능에서 재사용되는 것들을 먼저 만들어야 중복을 방지할 수 있습니다.**
- Phase 3-4에서 Notion API 함수, 타입, 컴포넌트를 반복적으로 사용합니다
- 공통 함수를 먼저 만들지 않으면 같은 코드를 여러 번 작성하게 됩니다
- 공통 컴포넌트의 디자인을 일관되게 유지하려면 미리 정의해야 합니다
- 타입 정의가 선행되면 TypeScript의 장점을 제대로 활용할 수 있습니다
- 한 번 만든 공통 모듈은 모든 기능에서 바로 사용 가능합니다

### 📋 개요
모든 기능에서 재사용될 공통 함수, 컴포넌트, 타입을 개발합니다. 이를 통해 코드 중복을 방지하고 일관성을 유지합니다.

### ⏱️ 예상 소요 시간
- **16-24시간** (2-3일)

### 📝 세부 작업

#### 2.1 Notion API 공통 함수 개발
```
목표: Notion 데이터 조회를 위한 재사용 가능한 함수 작성
파일: src/lib/notion.ts

작업:
- fetchAllPosts(): 모든 포스트 조회
  * Status = "발행됨" 필터링
  * Created date 역순 정렬
  * 페이지네이션 처리
  
- fetchPostBySlug(slug): 특정 포스트 조회
  * slug 기반 검색
  * 상세 콘텐츠 로드
  
- fetchPageBlocks(pageId): 페이지 블록 조회
  * 페이지의 모든 블록 가져오기
  * 블록 타입별 처리 준비
  
- fetchCategories(): 모든 카테고리 조회
  * Select 필드의 고유값 추출
  
- error handling 및 캐싱 로직

예상 시간: 4-5시간
```

#### 2.2 공통 컴포넌트 개발
```
목표: 모든 페이지에서 사용할 재사용 가능한 컴포넌트 작성
파일: src/components/

작업:
- Header.tsx: 상단 네비게이션
  * 로고, 메뉴, 검색바
  * 반응형 디자인
  
- Footer.tsx: 하단 정보
  * 저작권, 링크
  
- PostCard.tsx: 포스트 목록 카드
  * 제목, 요약, 카테고리, 날짜 표시
  * hover 효과
  
- PostList.tsx: 포스트 목록 컨테이너
  * 페이지네이션
  * 필터링 옵션
  
- CategoryBadge.tsx: 카테고리 배지
  
- TagBadge.tsx: 태그 배지
  
- Spinner.tsx: 로딩 상태

예상 시간: 5-7시간
```

#### 2.3 공통 타입 정의
```
목표: TypeScript 타입 정의로 타입 안정성 확보
파일: src/lib/types.ts

작업:
- Post 인터페이스
  * id, title, slug, category, tags
  * published, status, content
  * createdAt, updatedAt
  
- Category 타입

- PageBlock 타입 (Notion 블록)
  * paragraph, heading, image, code

예상 시간: 2-3시간
```

#### 2.4 유틸리티 함수 개발
```
목표: 자주 사용되는 함수들을 재사용 가능하게 작성
파일: src/lib/utils.ts

작업:

- getReadingTime(text): 읽기 시간 계산
```

## Phase 4: 추가 기능 개발 (2-3일)

### 🎯 왜 이 순서인가?
**핵심 기능이 완성된 후에야 부가 기능을 추가해야 합니다.**
- 검색, 필터, 카테고리 분류는 포스트 데이터가 있어야 테스트할 수 있습니다
- 핵심 기능이 불안정하면 추가 기능 개발이 방해받습니다
- 추가 기능은 핵심 기능이 어느 정도 검증된 후 추가하는 것이 효율적입니다
- 사용자 입장에서도 기본 기능부터 완성된 상태에서 부가 기능을 사용하는 것이 자연스럽습니다
- 우선순위 낮은 기능을 나중에 추가하면 시간이 부족해도 기본은 완성된 상태입니다

### 📋 개요
핵심 기능이 완성된 후, 사용자 경험을 향상시키는 부가 기능들을 추가합니다.

## Phase 5: 최적화 및 배포 (1-2일)

### 🎯 왜 이 순서인가?
**모든 기능이 완성된 후에 최적화하고 배포하는 것이 효율적입니다.**
- 기능이 변경되면 그동안의 최적화 작업이 무효화될 수 있습니다
- 미완성된 상태에서 배포하면 버그 수정 및 기능 추가가 번거로워집니다
- 최적화는 전체 코드를 대상으로 하므로 기능 개발이 끝난 후 하는 것이 낫습니다
- Lighthouse 점수, 성능 측정은 완성된 상태에서 의미 있는 결과를 보여줍니다
- 사용자들에게 안정적인 버전을 배포하는 것이 좋습니다

### 📋 개요
기능 개발이 완료된 후, 성능을 최적화하고 프로덕션 환경에 배포합니다.

### ⏱️ 예상 소요 시간
- **8-16시간** (1-2일)
